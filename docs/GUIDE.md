## 1. 适用场景

FnRelay 适合这样的环境：

- 飞牛 OS 上已经有一批需要域名和 HTTPS 的 Web 服务；
- 自己有域名，想让这些服务通过 `https://服务名.域名` 访问；
- 不想再维护一套独立的反向代理面板或管理后台；
- 希望管理入口只从飞牛桌面打开，不额外暴露管理端口。

它**不是**：

- 通用网站托管面板；
- 带用户注册/多租户的 SaaS 网关；
- 替代路由器的防火墙或端口扫描防护。

---

## 2. 前置条件

- 一台可安装 fpk 的飞牛 OS 设备；
- 飞牛管理员账号；
- 一个域名，并能修改 DNS；
- 路由器/NAT 的管理权限（如果要从公网访问）；
- 对应域名的证书（可使用飞牛证书中心签发，也可手动导入）。

检查清单：

```text
[ ] 域名解析到公网 IP 或内网 IP
[ ] 路由器可以把外部端口映射到 NAS
[ ] 飞牛 80/443 没有和其他服务冲突
[ ] 飞牛管理员能打开桌面应用
```

## 3. 安装

### 3.1 选择架构

| 设备 | 安装包 |
| --- | --- |
| x86_64 | `FnRelay-1.0.24-x86.fpk` |
| ARM64 | `FnRelay-1.0.24-arm.fpk` |

### 3.2 安装步骤

1. 打开飞牛 **应用中心**；
2. 选择 **手动安装**；
3. 选择对应 fpk；
4. 等待安装完成；
5. 回到飞牛桌面，点 **FnRelay** 图标。

### 3.3 从旧版升级

如果应用中心不允许直接覆盖升级，按下面做：

```text
卸载 FnRelay（保留数据）
→ 安装新版本 fpk
→ 从飞牛桌面打开
```

数据目录在：

```text
/volX/@appdata/fnrelay/
```

卸载应用不会删除这个目录，规则、设置、手动证书和日志都还在。

> 不建议直接删除 `@appdata/fnrelay`，除非确认不再需要配置和日志。

## 4. 第一次打开

FnRelay 没有独立的管理网址，也没有 FnRelay 登录密码。

正确入口：

```text
飞牛桌面 → FnRelay 图标
```

实际地址类似：

```text
https://你的飞牛域名/app/fnrelay
```

但不要在浏览器里单独打开这个地址，除非你确认飞牛网关已经带上管理员身份。直接打开可能看到：

```text
请从飞牛桌面打开
```

这是正常的权限保护，不是安装失败。

### 权限规则

- 只有飞牛管理员能打开；
- 普通用户访问会被拒绝；
- 退出飞牛账号后，FnRelay 也会失去访问权限；
- 不存在 FnRelay 自己的密码、登录页和退出按钮。

## 5. 添加第一条域名规则

打开 **域名规则 → 新建规则**。

示例：

```text
名称：app
域名：
  app.example.com
上游：
  http://127.0.0.1:8096
```

保存后，规则立即生效，不需要手动重启代理。

### 5.1 域名填写

支持：

```text
app.example.com      精确域名
*.example.com         泛域名
```

泛域名规则：

- 可以匹配多级子域，例如 `a.b.example.com`；
- 但 **证书** 不一定覆盖多级子域，见 [证书](#7-证书)。

多个域名可以写在同一条规则里，界面要求**每行一个**：

### 5.2 上游填写

常见上游：

```text
http://127.0.0.1:8080       服务 A
http://127.0.0.1:8081       服务 B
http://127.0.0.1:8082       服务 C
http://192.168.11.20:8080   局域网内另一台设备
https://127.0.0.1:9443      使用自签 HTTPS 的服务
```

如果上游使用自签证书，打开规则里的：

```text
忽略上游证书校验
```

这只影响 FnRelay 到上游这一段，不影响浏览器访问 FnRelay 的证书。

### 5.3 保留 Host

打开「保留 Host」后，FnRelay 会把用户访问的域名原样传给上游。

适合：

- 上游需要根据 Host 生成链接；
- 上游有多个虚拟站点；
- 上游的反向代理检查 Host。

不适合：

- 上游只接受 `127.0.0.1:端口` 这类 Host；
- 上游会因为有域名 Host 而拒绝请求。

### 5.4 自定义请求头

规则可以附加固定请求头，例如：

```text
X-Forwarded-Proto: https
X-Custom-Header: value
```

不需要时留空即可。FnRelay 默认已经会添加常用的 `X-Forwarded-*`。

## 6. 端口与路由器映射

### 6.1 代理端口

**设置 → 代理与跳转 → 代理端口**：

```text
443
```

这个端口同时处理：

- HTTPS（TLS）；
- 普通 HTTP（单端口复用）。

如果 443 被飞牛占用：

1. 飞牛 **系统设置 → 安全性 → 端口设置 → 高级设置**；
2. 取消勾选「重定向 80 和 443 端口」；
3. 回到 FnRelay 把代理端口改成 `443`；
4. 如果暂时不能占用 443，可先用 `8443` 或自定义端口。

### 6.2 额外 HTTP 端口

**额外 HTTP 跳转端口**是可选的第二个监听器，只负责 HTTP → HTTPS 跳转：

```text
填 0：关闭
填 80：访问 http://域名 时返回 308 跳到 HTTPS
```

特点：

- 只做跳转，不反代网页内容；
- 命中规则时**始终 308**，不受「HTTP 自动跳转 HTTPS」开关控制；
- 不参与证书选择；
- 80 被占用时启动失败，但不影响 443 主代理。

### 6.3 三种典型网络

#### A. 一个自定义外部端口

```text
外部 7777 → NAS 443
用户访问 https://app.example.com:7777
```

设置：

```text
代理端口：443
额外 HTTP 跳转端口：0
HTTP 自动跳转：开
跳转方式：保持用户访问的端口
```

效果：

```text
https://app.example.com:7777  → 正常访问
http://app.example.com:7777   → 跳到 https://app.example.com:7777
```

#### B. 外部 80/443 都映射到 NAS 443

```text
外部 80  → NAS 443
外部 443 → NAS 443
```

设置：

```text
代理端口：443
额外 HTTP 跳转端口：0
HTTP 自动跳转：开
跳转方式：保持用户访问的端口
```

效果：

```text
https://app.example.com → 正常
http://app.example.com  → 跳到 https://app.example.com
```

这里不需要额外 HTTP 80 监听，因为路由器已经把 80 转到 443。

#### C. HTTP 和 HTTPS 外部端口不同

```text
外部 HTTP 8080  → NAS 443
外部 HTTPS 7777 → NAS 443
```

设置：

```text
代理端口：443
HTTP 自动跳转：开
跳转方式：固定跳到指定端口
目标端口：7777
```

效果：

```text
http://app.example.com:8080 → https://app.example.com:7777
```

### 6.4 308 缓存警告

HTTP → HTTPS 使用 **308 Permanent Redirect**。

308 会被浏览器和部分客户端长期缓存。端口没最终确定前：

- 不要大规模发布；
- 不要随便改外部端口；
- 改端口后如果用户一直被带到旧地址，需要清理浏览器缓存或换域名测试。

## 7. 证书

### 7.1 自动加载飞牛证书

FnRelay 会扫描：

```text
/usr/trim/var/trim_connect/ssls/
/usr/trim/etc/network_gateway_cert.conf
/usr/trim/etc/network_cert_all.conf
```

典型目录：

```text
/usr/trim/var/trim_connect/ssls/<域名>/<时间戳>/<域名>.crt
/usr/trim/var/trim_connect/ssls/<域名>/<时间戳>/<域名>.key
/usr/trim/var/trim_connect/ssls/<域名>/<时间戳>/fullchain.crt
```

规则：

- `fullchain.crt` 优先作为证书链；
- 私钥按同名 `.key` 配对；
- `issuer_certificate.crt`、`intermediate.crt`、`ca.crt`、`root.crt` 等辅助证书自动跳过；
- 每 30 秒检查一次更新，续签后不需要重启。

### 7.2 手动导入

**证书 → 导入证书**：

```text
证书链：fullchain.crt 或 server.crt
私钥：server.key
```

也可以把证书放到一个目录，在 **设置 → 证书来源 → 附加证书目录** 里追加路径。

### 7.3 默认证书

当 SNI 没有匹配到任何证书时，使用默认证书。

如果不设置，FnRelay 会使用内置自签证书兜底，浏览器会提示证书不受信任。

### 7.4 泛域名证书的范围

`*.example.com` 通常只覆盖：

```text
a.example.com
b.example.com
```

不覆盖：

```text
a.b.example.com
```

虽然 FnRelay 的泛域名规则可以匹配多级子域，但证书不匹配时浏览器仍会报警。多级子域需要：

- 对应的多级泛域名证书；或
- 单独的完整域名证书。

### 7.5 没有证书的域名

没有证书时：

- HTTPS 会使用内置自签证书，浏览器提示不安全；
- 用户点继续后可以访问，但不适合公开发布；
- 当前「额外 HTTP 端口」只做跳转，不做 HTTP 反代。

如果需要纯 HTTP 访问，建议：

1. 给域名配证书；或
2. 关闭 HTTP 自动跳转，使用 `http://域名:代理端口` 访问；
3. 不要依赖额外 80 端口做纯 HTTP 反代，它只负责 308。

## 8. HTTP 跳转 HTTPS

设置 → **HTTP 自动跳转 HTTPS**。

### 8.1 保持用户访问的端口（推荐）

```text
http://app.example.com:7777 → https://app.example.com:7777
```

地址不带端口时：

```text
http://app.example.com → https://app.example.com
```

默认目标端口是 443。

### 8.2 固定跳到指定端口

```text
http://app.example.com:8080 → https://app.example.com:7777
```

适合：

- HTTP 和 HTTPS 外部端口不同；
- Host 里没有端口，但你知道固定 HTTPS 端口；
- 想统一把所有 HTTP 跳到一个标准入口。

### 8.3 额外 HTTP 端口的行为

额外 HTTP 端口（例如 80）是独立入口：

- 命中规则 → 始终 308；
- 不受“HTTP 自动跳转”开关影响；
- 不命中规则 → 404；
- 不做反代。

## 9. 泛域名与批量替换

### 9.1 泛域名

规则：

```text
*.example.com
```

可以匹配：

```text
app.example.com
app.example.com
a.b.example.com
```

精确域名优先于泛域名，越长泛域名优先。

### 9.2 批量替换域名后缀

**域名规则 → 批量替换域名**。

示例：

```text
原后缀：s.com
新后缀：c.com
```

会替换：

```text
1.s.com      → 1.c.com
2.s.com      → 2.c.com
a.b.s.com    → a.b.c.com
*.s.com      → *.c.com
s.com        → c.com
```

不会替换：

```text
nots.com
```

因为 `nots.com` 不是 `s.com` 的子域。

规则：

- 弹窗会先显示预览；
- 确认后才保存；
- 规则名称、上游、备注、证书提示不变；
- 替换后如果新域名和其他规则冲突，会拒绝；
- 同一规则内出现重复也会拒绝；
- 替换动作写审核日志；
- 替换后请确认证书覆盖新域名。

## 10. 实时访问

侧栏 **实时** 页只显示当前还没结束的请求：

```text
用户 IP | 服务域名 | 路径 | 状态 | 下行 | 上行 | 持续 | 上游
```

特点：

- 1 秒刷新；
- 顶部显示活动请求数、总下行、总上行；
- 概览页也有「正在访问」卡片；
- HTTP、流式响应、SSE、WebSocket 都会统计上下行字节；
- 速度按每秒字节差计算，短请求可能显示 `0 B/s`；
- 只存内存，不落盘；请求结束后从实时表消失；
- 完整记录去「日志」页看。

## 11. 日志

日志页分三类：

- **访问**：每个代理请求；
- **审核**：规则、设置、证书操作；
- **系统**：启动、端口、证书加载等事件。

访问日志包含：

```text
时间 / request_id / 客户端 IP / remote_addr / X-Real-IP / XFF
IP 来源 / 域名 / 方法 / 路径 / 查询 / 协议 / HTTP 版本
状态码 / 耗时 / 响应字节 / 请求字节 / 规则 / 上游
User-Agent / Referer / 错误
```

隐私处理：

- 代理请求的真实 IP 取 TCP 对端；
- 客户端自带的 XFF 只记录，不作为真实 IP；
- 查询参数里的 `token`、`password`、`key`、`code`、`sig` 会打码；
- 不记录 Cookie、Authorization、请求体、证书私钥。

### 本地保存

设置 → 日志 → **保存日志到本地**（默认关闭）：

```text
目录：@appdata/fnrelay/logs/
文件：access-YYYY-MM-DD.jsonl
      audit-YYYY-MM-DD.jsonl
      system-YYYY-MM-DD.jsonl
```

- 保留 1–7 天，默认 7 天；
- 跨天自动切文件；
- 单日单文件默认上限 100MB；
- 超限当天停止写入并计数；
- 文件权限 `0600`；
- 访问日志异步写入，队列满会丢弃，不阻塞代理。

## 12. 备份与恢复

设置 → **备份与恢复**。

### 12.1 下载备份

导出：

```text
fnrelay-backup-<版本>-<时间>.json
```

包含：

```text
format       fnrelay-backup
schema       备份格式版本
version      FnRelay 版本号
created_at   导出时间
config.proxy
config.certs
config.logs
config.rules
```

不包含：

- 证书私钥；
- 密码哈希；
- 日志文件；
- 当前会话。

### 12.2 恢复

选择备份文件 → 预览/确认 → 恢复。

恢复必须同时满足：

```text
format == fnrelay-backup
schema == 当前支持版本
version == 当前 FnRelay 版本
```

版本不一致会拒绝：

```text
版本不一致：备份为 1.0.20，当前为 1.0.24
```

这是有意设计：不同版本的配置结构可能不兼容，不自动猜测迁移。

### 12.3 恢复会覆盖什么

- 代理端口、跳转、HSTS、默认上游；
- 证书目录、默认证书；
- 日志设置；
- 全部域名规则。

恢复后代理会按需重启；端口变化时页面可能短暂断开。

## 13. 升级、卸载与数据

### 13.1 升级

1. 下载新版本 fpk；
2. 应用中心手动安装；
3. 如果应用中心不允许直接覆盖升级：

```text
卸载（保留数据）→ 安装新版本
```

4. 安装后在「设置 → 备份与恢复」重新下载一份当前版本备份。

> 因为恢复要求版本完全一致，升级后旧版本备份不能直接恢复。

### 13.2 数据目录

```text
/volX/@appdata/fnrelay/
├── config.json       规则、端口、证书、日志设置
├── certs/            手动导入的证书
├── selfsigned.crt    内置自签回退证书
├── selfsigned.key
└── logs/
    ├── fnrelay.log
    ├── access-YYYY-MM-DD.jsonl
    ├── audit-YYYY-MM-DD.jsonl
    └── system-YYYY-MM-DD.jsonl
```

安装目录：

```text
/volX/@appcenter/fnrelay/target/
```

这里只放程序，不写配置和日志。

### 13.3 彻底清理

确认不再需要配置后，再手动删除：

```text
/volX/@appdata/fnrelay/
```

普通卸载不会删除它。

## 14. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 打开提示「请从飞牛桌面打开」 | 不是从飞牛桌面进入，或网关没带管理员身份 | 从飞牛桌面点 FnRelay 图标 |
| 403 | 当前账号不是飞牛管理员 | 换管理员账号 |
| 404 页面不存在 | 域名没命中规则，或规则停用 | 检查域名、规则开关、泛域名 |
| 502 服务暂时不可用 | 上游没启动、端口错、协议错 | 检查上游地址和端口 |
| 浏览器证书警告 | 证书不覆盖当前域名，或用了自签兜底 | 检查 SNI、泛域名范围、默认证书 |
| `http://域名` 打不开 | 80 没监听，或路由器没把 80 转到 443 | 配额外 HTTP 端口，或改路由器映射 |
| HTTP 跳转到了错误端口 | Host 没端口，或 HTTP/HTTPS 外部端口不同 | 用「固定跳到指定端口」 |
| 改端口后一直跳旧地址 | 308 被浏览器缓存 | 清缓存，或换域名测试 |
| 443 启动失败 | 被飞牛或其他程序占用 | 关闭飞牛 80/443 重定向，或换端口 |
| 80 启动失败 | 被其他程序占用 | 关闭额外 HTTP 端口，或释放 80 |
| 日志没有文件 | 「保存日志到本地」没开 | 设置 → 日志 → 打开 |
| 备份恢复失败 | 版本不一致 / 格式不对 / 配置冲突 | 用同版本备份，检查 JSON |
| 管理页空白 | 飞牛网关/iframe 加载失败 | 刷新、重新从桌面打开、检查网关 |

### 诊断顺序

```text
1. FnRelay 是否 running
2. 代理端口是否在监听
3. 域名规则是否命中
4. 上游是否能从 NAS 访问
5. 证书是否覆盖域名
6. 路由器端口映射是否正确
```

## 15. 安全与限制

### 安全

- 管理界面只走飞牛统一网关，没有独立管理端口和 FnRelay 密码；
- 修改类 API 需要自定义请求头，降低跨站表单提交风险；
- 公开错误页不显示域名、上游、规则名、后台入口；
- 证书私钥只存 NAS 本地；
- 备份不包含私钥和密码哈希。

### 限制

- 客户端侧 HTTP/1.1，不启用 h2；
- 不读取 `X-Forwarded-Proto` 判断原始协议；前面有 CDN/反代终止 TLS 时，HTTP 跳转可能不正确；
- 泛域名证书通常只覆盖一级子域；
- 308 会缓存，HSTS 更难回退；
- 规则不支持路径前缀分流；
- 没有证书的域名不适合公开发布；
- 额外 HTTP 端口只跳转，不反代。

## 16. FAQ

### Q：为什么没有 8899 管理端口？

A：管理界面只通过飞牛网关的 Unix Socket 访问，不再暴露独立管理网页端口。

### Q：为什么没有 FnRelay 密码？

A：权限完全跟随飞牛登录态，只有飞牛管理员能进入。退出飞牛账号就没有权限。

### Q：一个端口真的能同时接 HTTP 和 HTTPS 吗？

A：可以。FnRelay 读取连接的第一个字节，TLS 走 HTTPS，否则按 HTTP 处理。

### Q：能反代 WebSocket 吗？

A：可以，实时页也会统计 WebSocket 双向字节。

### Q：能反代 SSE / 流式响应吗？

A：可以，SSE 和流式响应按普通 HTTP 流处理。

### Q：支持 HTTP/2 吗？

A：当前客户端侧只声明 HTTP/1.1，不启用 h2。

### Q：能自动申请 Let's Encrypt 证书吗？

A：不负责签发。使用飞牛证书中心签发的证书，或手动导入已有证书。

### Q：支持多级泛域名吗？

A：规则可以匹配，但 `*.example.com` 证书通常不覆盖 `a.b.example.com`，需要对应证书。

### Q：升级后旧备份为什么不能恢复？

A：备份带版本号，恢复要求完全一致，避免配置结构不兼容。升级后重新下载当前版本备份。

### Q：卸载会删除配置吗？

A：不会。配置、证书、日志在 `@appdata/fnrelay`，卸载应用不会删除；需要彻底清理时手动删。
